1.1 ความเป็นมาและความสำคัญของปัญหา
         อารีน่า หัวหิน (Arena Hua Hin) หรือเดิมชื่อ ทรู อารีน่า หัวหิน (True Arena Hua Hin) เป็น
โครงการศูนย์ฝึกซ้อมและแข่งขันกีฬาระดับพรีเมียมในเครือกลุ่มบริษัท พราว (Proud Group) ซึ่งรวมถึง
บริษัท พราว เรียล เอสเตท จำกัด (มหาชน) (Proud Real Estate Public Company Limited) จากการที่
ผู้รายงานได้เข้าปฏิบัติงานสหกิจศึกษา ณ สถานประกอบการแห่งนี้ พบว่าอารีน่า หัวหิน ให้ความสำคัญอย่าง
ยิ่งกับการบริหารจัดการระบบเทคโนโลยีสารสนเทศและการสนับสนุนทางด้านไอที (IT Support) โดยมีการ
จัดสรรและดูแลรักษาระบบให้มีความทันสมัยและเป็นมาตรฐานสากลระดับสูง เช่นเดียวกับสถานประกอบการ
ระดับพรีเมียมแห่งอื่น ๆ ในเครือพราว กรุ๊ป
        ในโครงสร้างการทำงานรายวันของอารีน่า หัวหิน อุปกรณ์ไอทีและระบบเครือข่ายทำหน้าที่เป็นแกน
หลักสำคัญในการดำเนินธุรกิจ ไม่ว่าจะเป็นการกระจายสัญญาณเครือข่ายอินเทอร์เน็ตความเร็วสูงเพื่ออำนวย
ความสะดวกให้แก่ลูกค้า พนักงาน และแขกผู้มีเกียรติที่เข้ามาร่วมกิจกรรมต่าง ๆ ในพื้นที่ การให้บริการระบบ
จองคิวและจองเวลาใช้บริการเครื่องมืออุปกรณ์ การแชร์ไฟล์ข้อมูลร่วมกันภายในองค์กร ตลอดจนอุปกรณ์
อัจฉริยะส่วนใหญ่ที่เชื่อมโยงระบบการทำงานเข้าด้วยกันผ่านเครือข่ายอินเทอร์เน็ต เพื่อสร้างประสิทธิผลและ
อำนวยความสะดวกสูงสุดในการดำเนินงานรายวัน
         อย่างไรก็ตาม จากการเก็บข้อมูลและการปฏิบัติงานอย่างใกล้ชิด ผู้รายงานพบว่าอุปกรณ์ร ะบบ
เครือข่ายและระบบประมวลผลส่วนใหญ่ในองค์กรเป็นอุปกรณ์ที่มีอายุการใช้งานค่อนข้างมาก แต่ยังสามารถ
รักษาสมรรถนะการทำงานที่ดีและรองรับความต้องการใช้งานหนักในแต่ละวันไว้ได้เนื่องจาก มี "ระบบการ
ตรวจเช็คสภาพอุปกรณ์ไอทีรายวัน" (Daily System Checklist) ที่เข้มงวดและสม่ำเสมอ ซึ่งทำหน้าที่คอย
ตรวจสอบ ตรวจหาความผิดปกติ และบำรุงรักษาเชิงป้องกันก่อนที่อุปกรณ์จะขัดข้อง
        อย่างไรก็ตาม ระบบบัน ทึกและตรวจสอบสถานะไอทีรายวันในปัจจุบันยังคงทำงานและจัดเก็บ
ฐานข้อมูลอยู่บนเครื่องเซิร์ฟเวอร์หลักภายในสถานประกอบการ (On-Premises Server) ร่วมกับซอฟต์แวร์
ระบบอื่น ๆ ขององค์กร ผู้รายงานจึงเล็งเห็นว่ามีโอกาสและความเหมาะสมที่จะทดลองแยกบางระบบงานที่
สามารถดำเนินงานแบบอิสระได้ ออกมาทำงานบนสภาพแวดล้อมระบบคลาวด์ (Cloud Environment) เพื่อ
ลดความซ้ำซ้อนของการใช้ทรัพยากรบนเครื่องเซิร์ฟเวอร์หลัก และเป็นการทดสอบแนวทางปรับปรุงระบบการ
ทำงานให้มีความคล่องตัวทันสมัยยิ่งขึ้น
      ด้วยเหตุนี้ ผู้รายงานจึงได้เสนอแนวคิดในการย้ายระบบตรวจเช็คสภาพไอทีรายวันดังกล่าวขึ้นไป
ทำงานบนเทคโนโลยี ค ลาวด์ "Google Firebase" ซึ ่ ง นอกจากจะเป็ น การศึ ก ษาทดลองและประเมิ น
ประสิทธิภาพของการประยุกต์ใช้งานเทคโนโลยีคลาวด์ในสถานประกอบการจริงแล้ว ยังเป็นโอกาสอันดีในการ
ดำเนินการปรับปรุงระบบเดิมแบบบูรณาการ (System Overhaul) เพื่อขจัดข้อจำกัดทางเทคนิคและฟังก์ชัน
การใช้งานของแบบฟอร์มเดิมที่มีอยู่ ให้สามารถปรับแต่งได้อย่างยืดหยุ่นและตอบโจทย์การปฏิบัติงานของ
เจ้าหน้าที่ไอทีซัพพอร์ตได้ดียิ่งขึ้น โดยรายละเอียดของฟีเจอร์สำคัญและแนวทางการพัฒนาระบบจะระบุไว้โดย
ละเอียดในหัวข้อถัด ๆ ไปที่เกี่ยวข้อง

1.2 วัตถุประสงค์ของการปฏิบัติงาน
       1.2.1 เพื่อพัฒนาเว็บแอปพลิเคชันสำหรับบันทึกและตรวจสอบสถานะโครงสร้างพื้นฐานไอทีรายวัน
   แบบเรียลไทม์ เพื่อย้ายระบบการทำงานบางส่วนออกจากเซิร์ฟเวอร์หลักของสถานประกอบการและแก้ไข
   ข้อจำกัดของระบบเดิม
       1.2.2 เพื่อศึกษาและประยุกต์ใช้บริการคลาวด์เทคโนโลยีของ Google Firebase ทั้งระบบจัดการ
   ฐานข้อมูล (Firestore Database) การยืนยันตัวตนผู้ใช้งาน (Firebase Authentication) และการโฮสต์
   เว็บแอปพลิเคชัน (Firebase Hosting) ร่วมกับการปฏิบัติงานจริงในสถานประกอบการ
      1.2.3 เพื่อพัฒนาระบบรักษาความปลอดภัยในการเข้าใช้งานและการจัดการสิทธิ์ผู้ใช้ (Role-based
   Access Control) โดยแบ่งสิทธิ์ความรับผิดชอบและการเข้าถึงเมนูต่าง ๆ ระหว่างผู้ดูแลระบบ (Admin)
   และเจ้าหน้าที่ปฏิบัติงาน (Staff)
        1.2.4 เพื่อออกแบบและพัฒนาฟังก์ชันการจัดการรายการอุปกรณ์แบบยืดหยุ่น (Dynamic Checklist
   Management) ซึ่งเปิดโอกาสให้ผู้ใช้งานสามารถเพิ่ม แก้ไข หรือลบหัวข้ออุปกรณ์ในแบบฟอร์มตรวจสอบ
   ได้เองตามการเปลี่ยนแปลงของอุปกรณ์จริงในอนาคต โดยไม่จำเป็นต้องแก้ไขซอร์สโค้ดของแอปพลิเคชัน
   โดยตรง
       1.2.5 เพื่อปรับปรุงภาพรวมโครงสร้างระบบทั้งหมด (System Overhaul) และพัฒนาส่วนหน้า
   จอแสดงผลข้อมูลสรุป (Dashboard) ที่แสดงข้อมูลสถานะระบบรายเดือนแบบเข้าใจง่าย เพื่อสนับสนุน
   การวางแผนแล ะการตั ด สิ น ใจเชิ ง การบริ ห ารจั ด การระบบไอที ข องสถานประกอบการ
1.3 ขอบเขตของการปฏิบัติงาน
         เพื่อให้การดำเนินงานพัฒนาแอปพลิเคชันเป็นไปอย่างมีประสิทธิภาพและบรรลุวัตถุประสงค์ที่ตั้งไว้
ผู้รายงานได้กำหนดขอบเขตของการปฏิบัติงานสหกิจศึกษาออกเป็น 4 ด้านหลัก ดังต่อไปนี้
              1.3.1 ขอบเขตด้านสถาปัตยกรรมและเทคโนโลยีของระบบ (System & Technology
       Architecture)
                   1.3.1.1 ส่วนติดต่อผู้ใช้งาน (Frontend): พัฒนาด้วยภาษาระดับมาตรฐาน ได้แก่
               HTML5, CSS3 และ JavaScript (Vanilla JS / Modern ES6) โดยเน้นรูปแบบการดีไซน์ที่มี
               โครงสร้างยืดหยุ่น (Responsive Web Design) เพื่อให้แอปพลิเคชันสามารถแสดงผลและใช้
               งานได้อย่างราบรื่นทั้งบนหน้าจอคอมพิวเตอร์เดสก์ท็อป แท็บเล็ต และสมาร์ตโฟน
                    1.3.1.2 ระบบบริการคลาวด์หลังบ้าน (Cloud Backend Services): ประยุกต์ใช้งาน
               แพลตฟอร์ม Google Firebase เป็นแกนหลักในการขับเคลื่อนระบบ ประกอบด้วยบริการ
               ต่าง ๆ ดังนี้:
                        - Firebase Authentication: ใช้สำหรับระบุและตรวจสอบตัวตนผู้ใช้งานด้วย
                              การลงทะเบียนผ่านอีเมลและรหัสผ่าน (Email & Password Authentication)
                              เพื่อคัดกรองการเข้าถึงหน้าเว็บแอปพลิเคชัน
                        - Cloud Firestore: ใช้ ร ะบบฐานข้ อ มู ล ประเภท NoSQL Document
                          Database สำหรับจัดเก็บข้อมูลโครงสร้างแบบฟอร์มตรวจสอบ ประวัติบันทึก
                          สถานะอุปกรณ์รายวัน และประวัติล็อกอินของผู้ใช้งานในลักษณะโครงสร้าง
                          Collection และ Document
                        - Firebase Hosting: ใช้เป็นพื้นที่จัดเก็บและเผยแพร่ (Deploy) ส่วนหน้าจอ
                          ผู้ใช้งาน (Static Web Assets) ขึ้นสู่ระบบคลาวด์อินเทอร์เน็ต เพื่อให้เจ้าหน้าที่
                          สามารถเข้าใช้งานได้จากทุกที่ทุกเวลา

               1.3.2 ขอบเขตด้านฟังก์ชันการทำงานของระบบ (Functional Specifications)
                        ระบบเว็บแอปพลิเคชันที่พัฒนาขึ้นจะแบ่งโมดูลการทำงานและฟังก์ชันหลักออกเป็น
               5 โมดูล ดังนี้:
      1.3.2.1 ระบบบริ ห ารจั ด การสมาชิ ก และกำหนดสิ ท ธิ ์ ผ ู ้ ใ ช้ ง าน
(Authentication & Role Management):
       - ระบบตรวจสอบสิทธิ์ในการเข้าถึงหน้าใช้งานผ่านระบบล็อกอิน (Login
         / Logout)
       - การจัดสรรระดับสิทธิ์ผู้ใช้งาน (Role Privilege) เป็น 2 ระดับ:
               - ระดับเจ้าหน้าที่ (Staff): มีสิทธิ์เข้าใช้งานระบบบันทึกผล
                 ตรวจสอบไอทีรายวัน เรียกดูข้อมูลปฏิทินสถานะย้อนหลั ง
                 และดูสรุปข้อมูลบนแดชบอร์ด
               - ระดับผู้ดูแลระบบ (Admin): มีสิทธิ์เทียบเท่าระดับ Staff
                 และมีสิทธิ์เพิ่มเติมในการจัดการโครงสร้างเช็คลิสต์ทั้งหมด
                 (เพิ่ม/ลบรายการอุปกรณ์) รวมถึงการตั้งค่าบัญชีผู้ใช้งาน
                 ระบบ

      1.3.2.2 ระบบแบบฟอร์มตรวจเช็คสภาพอุปกรณ์ไอทีรายวัน (Daily
System Checklist Form):

                - เป็นศูนย์สปอร์ตคอมเพล็กซ์ที่ครบวงจรและดีที่สุดในกลุ่มประชาคมเศรษฐกิจอาเซียน
                    (AEC) ด้วยการส่งมอบการฝึกสอน อุปกรณ์ ตลอดจนสิ่งอำนวยความสะดวกระดับมือ
                    อาชีพ
                - รองรับและริเริ่มการเป็นเจ้าภาพจัดการแข่งขันกีฬาระดับมาตรฐานสากลอย่างต่อเนื่อง
                    ตลอดทั้งปี เพื่อขับเคลื่อนเศรษฐกิจเชิงกีฬา (Sports Economy) ของประเทศอย่าง
                    ยั่งยืน


1.5 ประโยชน์ที่คาดว่าจะได้รับ
        การดำเนินงานพัฒนาแอปพลิเคชันระบบบันทึกและตรวจสอบสถานะโครงสร้างพื้นฐานไอทีรายวัน
แบบเรียลไทม์ด้วยเทคโนโลยีคลาวด์ไฟร์เบสในครั้งนี้ คาดว่าจะก่อให้เกิดประโยชน์ในด้านต่าง ๆ ดังนี้

        1.5.1 ประโยชน์ต่อสถานประกอบการ (อารีน่า หัวหิน)

                1.5.1.1 ลดภาระการทำงานและการพึ่งพิงเครื่องเซิร์ฟเวอร์หลัก: สถานประกอบการมี
        ระบบตรวจเช็คสถานะไอทีรายวันแบบแยกอิสระ (Decoupled System) บนระบบคลาวด์ ช่วยลด
        ความซ้ำซ้อนของการประมวลผลบนเครื่องเซิร์ฟเวอร์หลัก (On-Premises Server) และประกันความ
        ต่อเนื่องของงานไอทีซัพพอร์ตแม้ในกรณีที่ระบบเซิร์ฟเวอร์ส่วนกลางของบริษัทเกิดขัดข้อง
        1.5.1.2 เพิ่มประสิทธิภาพและลดเวลาการรายงานผลของเจ้า หน้า ที่: เจ้าหน้าที่ไอที
สามารถเข้าใช้งานแบบฟอร์มตรวจสอบสถานะอุปกรณ์แบบเรียลไทม์ผ่านอุปกรณ์เคลื่อนที่ในขณะ
ปฏิบัติงานตรวจเช็คภาคสนามได้อย่างคล่องตัว ช่วยทดแทนระบบจัดการฐานข้อมูลแบบเดิมที่จำกัด
ช่องทางการเข้าถึง

        1.5.1.3 มีความยืดหยุ่นในการปรับแต่งระบบอย่างสะดวกและปลอดภัย: ผู้ดูแลระบบ
สามารถบริหารจัดการ เพิ่ม หรือลดรายการอุปกรณ์ไอทีในฟอร์มตรวจสอบได้เองในสภาวะจริง เพื่อให้
สอดรับกับการเปลี่ยนแปลงทางกายภาพของโครงสร้างระบบโดยไม่มีความจำเป็นต้องพึ่งพิงการแก้ไข
โค้ดโปรแกรม

        1.5.1.4 สนับสนุนการบริหารจัดการระบบและวางแผนบำรุงรักษาเชิงป้องกัน: ข้อมูลสถิติ
และสถานะภาพรวมของระบบไอทีที่สรุปผ่านหน้าหน้าจอแสดงผลข้อมูล (Dashboard) และรายงาน
รายเดือน ช่วยให้ผู้บริหารระดับสูงหรือหัวหน้างานไอทีสามารถนำข้อมูลไปใช้ประกอบการตัดสินใจ
ป้องกันปัญหาอุปกรณ์หยุดทำงานกะทันหัน (Downtime) ได้อย่างแม่นยำยิ่งขึ้น


1.5.2 ประโยชน์ต่อผู้รายงาน (นักศึกษาปฏิบัติงานสหกิจศึกษา)

        1.5.2.1 พัฒนาทักษะการออกแบบและพัฒนาเว็บแอปพลิเคชันขั้นสูง: ได้เพิ่มพูนความรู้
ความเข้าใจ และทักษะเชิงลึกในการพัฒนาซอฟต์แวร์ประยุกต์ด้วย HTML5, CSS3 และ JavaScript

        1.5.2.2 เข้ า ใจและสามารถประยุ ก ต์ ใช้ ง านเทคโนโลยี ค ลาวด์ ข ั ้ น พื ้ น ฐาน: ได้ รั บ
ประสบการณ์ตรงจากการปฏิบัติงานจริงร่วมกับระบบฐานข้อมูล NoSQL (Cloud Firestore) ระบบ
ลงทะเบียนผู้ใช้คลาวด์ (Firebase Authentication) และการนำเสนอระบบขึ้นสู่บริการโฮสติ้งคลาวด์
(Firebase Hosting) ซึ่งเป็นเทคโนโลยีที่ได้ความนิยมสูงในอุตสาหกรรมซอฟต์แวร์ในปัจจุบัน

        1.5.2.3 ฝึกทักษะการทำงานวิศวกรรมระบบแบบบูรณาการ (System Overhaul): มี
โอกาสวิเคราะห์ วางโครงสร้างสถาปัตยกรรมระบบ แก้ไขปัญหาเชิงเทคนิค และย้ายระบบการทำงาน
จริงเข้าสู่สภาวะคลาวด์ภายใต้ขอบเขตการรักษาความปลอดภัยของข้อมูลบริษัท

        1.5.2.4 เรียนรู้ทักษะการทำงานร่วมกับองค์กรอย่างเป็นระบบ: ได้เข้าใจในวัฒนธรรม
องค์กร กระบวนการทำงานร่วมกับผู้เชี่ยวชาญด้านไอทีระดับมืออาชีพ และการแก้ไขปัญหาเฉพาะ
หน้าในแวดวงสปอร์ตคลับและสปอร์ตทัวริสซึมชั้นนำอย่างเป็นรูปธรรม
1.5.3 ประโยชน์ต่อมหาวิทยาลัยและแวดวงวิชาการ

       1.5.3.1 เป็นแหล่งอ้างอิงและกรณีศึกษาสำหรับนักศึกษารุ่นหลัง: รายงานฉบับนี้สามารถ
ใช้เป็นกรณีศึกษา (Case Study) และแนวทางเปรียบเทียบสำหรับการทำโครงงานในระดับปริญญาตรี
ของสาขาวิชาเทคโนโลยีวิศวกรรมคอมพิวเตอร์ ในหัวข้อที่เกี่ยวเนื่องกับการพัฒนาสแต็กเทคโนโลยี
ระบบคลาวด์ทดแทนระบบแบบเดิม (On-Premises Migration)

       1.5.3.2 เสริมสร้างภาพลักษณ์และความร่วมมือระหว่างสถาบันกับภาคเอกชน: ช่วย
ส่งเสริมมาตรฐานทางวิชาการและชื่อเสียงของมหาวิทยาลัยเทคโนโลยีราชมงคลรัตนโกสินทร์ วิทยา
เขตวังไกลกังวล ผ่านผลงานการพัฒนาแอปพลิเคชันที่นำไปใช้งานได้จริงและสร้างประโยชน์ให้กับ
พันธมิตรเครือข่ายภาคธุรกิจชั้นนำระดับประเทศอย่างกลุ่มบริษัท พราว (Proud Group)

2.1 ที่มา
        ในระหว่างการปฏิบัติงานสหกิจศึกษาในบทบาทเจ้าหน้าที่สนับสนุนด้านเทคโนโลยีสารสนเทศ (IT
Support) ณ อารีน่า หัวหิน ผู้รายงานได้รับมอบหมายให้ดูแลและตรวจสอบความพร้อมใช้งานของระบบ
โครงสร้างพื้นฐานไอทีเป็นประจำทุกวัน ซึ่งกระบวนการตรวจเช็คดังกล่าวถือเป็นภารกิจหลักในการควบคุมและ
ป้องกันปัญหาขัดข้องของระบบก่อนที่จะส่งผลกระทบต่อผู้ใช้บริการ

        จากการปฏิบัติงานดังกล่าว ผู้รายงานพบว่าระบบแบบฟอร์มตรวจสอบเดิมทำงานอยู่บนเว็บเซิร์ฟเวอร์
ภายในองค์กร (On-Premises Server) โดยทำงานผ่านระบบจำลองเว็บเซิร์ฟเวอร์ (XAMPP) และระบบ
ฐานข้อมูล (MySQL) ซึ่งระบบเซิร์ฟเวอร์หลักนี้ต้องรองรับซอฟต์แวร์ประยุกต์อื่น ๆ ของสถานประกอบการร่วม
ด้วยเป็นจำนวนมาก ผู้รายงานร่วมกับพนักงานที่ปรึกษาจึงได้ตกผลึกแนวคิดร่วมกันว่า สมควรที่จะแยกและ
ย้ายระบบงานตรวจสอบสถานะไอทีรายวันนี้ออกจากเครื่องเซิร์ฟเวอร์หลัก เพื่อไปทำงานบนสถา ปัตยกรรม
คลาวด์ไร้เซิร์ฟเวอร์ (Serverless Cloud Architecture) ของ Google Firebase

        โครงงานนี้จ ึงถูกริเริ่มขึ้น เพื่อพัฒนาเว็บแอปพลิเคชันเวอร์ช ันใหม่ในลักษณะการรื้อปรับระบบ
(System Overhaul) ที่ไม่เพียงแต่ย้ายสัญญานขึ้นสู่คลาวด์เพื่อความปลอดภัยและเสถียรภาพเท่านั้น แต่ยัง
มุ่งเน้นการปรับปรุงฟังก์ชันการใช้งานและการจัดการแบบฟอร์มให้มีความคล่องตัว ยืดหยุ่น และตอบสนองต่อ
การปฏิบัติงานไอทีซัพพอร์ตของหน่วยงานได้อย่างสมบูรณ์ยิ่งขึ้น


2.2 ทฤษฎีที่เกี่ยวข้อง

        ในการดำเนินงานพัฒนาเว็บแอปพลิเคชันระบบบันทึกและตรวจสอบสถานะโครงสร้างพื้นฐานไอที
รายวันด้วยเทคโนโลยีคลาวด์ไฟร์เบส ผู้รายงานได้ทำการศึกษา ค้นคว้า และประยุกต์ใช้หลักการ ทฤษฎี
ตลอดจนเทคโนโลยีต่าง ๆ ที่เกี่ยวข้องเพื่อให้การพัฒนาสถาปัตยกรรมระบบเป็นไปอย่างถูกต้องต ามหลั ก
วิศวกรรมคอมพิวเตอร์ โดยมีรายละเอียดดังต่อไปนี้
     2.2.1 ทฤษฎี ก ารพั ฒ นาเว็ บ แอปพลิ เ คชั น และส่ ว นติ ด ต่ อ ผู ้ ใช้ ง าน (Web Application
Development)

             การพัฒนาส่วนติดต่อผู้ใช้งาน (Frontend) ของแอปพลิเคชันนี้ อาศัยองค์ประกอบของ
     เทคโนโลยีเว็บพื้นฐานที่ทำงานร่วมกันบนเว็บเบราว์เซอร์ของฝั่งผู้ใช้ (Client-Side) ดังนี้:

                      2.2.1.1 HTML5 (HyperText Markup Language 5): เป็นภาษาโครงสร้าง
             พื้นฐานในการจัดวางองค์ประกอบต่าง ๆ บนหน้าเว็บเพจ โดย HTML5 ได้รับการพัฒนาให้มี
             สแตนดาร์ดแท็กเชิงความหมาย (Semantic Tags)
             เช่น <header>, <nav>, <section>, <article> และ <aside> ซึ่งช่วยให้สถาปัตยกรรม
             การจัดลำดับชั้นข้อมูลมีความเป็นระเบียบ และเอื้อประโยชน์ต่อการทำงานร่วมกับสคริปต์
             ภายนอก

                      2.2.1.2 CSS3 (Cascading Style Sheets 3): เป็นเทคโนโลยีที่ใช้ก ำหนด
             คุณลักษณะ รูปแบบ การแสดงผล และแอนิเมชันของส่วนติดต่อผู้ใช้ โดยในโครงงานนี้มีการ
             ประยุกต์ใช้คุณสมบัติ Media Queries ซึ่งเป็นทฤษฎีพื้นฐานของ Responsive Web
             Design เพื ่ อ ช่ ว ยในการจั ด วางเลย์ เ อาต์ (Layout Dynamic Grid) และปรั บ ขนาด
             ส่วนประกอบต่าง ๆ ให้เหมาะสมกับขนาดความกว้างหน้าจอของอุปกรณ์ที่แตกต่างกันโดย
             อัตโนมัติ (เช่น สมาร์ตโฟน แท็บเล็ต และเดสก์ท็อป)

                      2.2.1.3 JavaScript (ES6+): เป็นภาษาสคริปต์ระดับสูงแบบตีความ (Interpreted
             Language) ที ่ ท ำงานฝั ่ ง Client-Side เพื ่ อ ตอบสนองต่ อ เหตุ ก ารณ์ (Event-Driven
             Programming) เช่น การคลิกปุ่ม การส่งค่าฟอร์ม และทำหน้าที่หลักในการจัดเตรียมข้อมูล
             เพื่อเรียกใช้งานและสื่อสารแบบอะซิงโครนัส (Asynchronous Communication) กับ
             ชุดคำสั่ง API ของ Google Firebase โดยไม่ต้องโหลดหน้าเว็บเพจใหม่ทั้งหมด (Single
             Page Feel)
       2.2.2 สถาปัตยกรรมระบบคลาวด์และการประมวลผลแบบไร้เซิร์ฟเวอร์ (Cloud Computing &
Serverless)

                2.2.2.1 คลาวด์คอมพิวเตอร์ (Cloud Computing): เป็นระบบที่ให้ผู้ใช้งานสามารถเข้าถึง
       ทรัพยากรระบบคอมพิวเตอร์ เช่น พื้นที่จัดเก็บข้อมูล หน่วยประมวลผล และซอฟต์แวร์ ผ่านเครือข่าย
       อินเทอร์เน็ต โดยผู้ใช้งานไม่จำเป็นต้องเป็นเจ้าของและดูแลรักษาโครงสร้างพื้นฐานเชิงกายภาพ
       (Physical Hardware)

                2.2.2.2 Backend-as-a-Service (BaaS): เป็นรูปแบบย่อยของการให้บริการคลาวด์ที่ผู้
       ให้บริการจะเตรียมส่วนหลังบ้าน (Backend API, Database, Authentication, Hosting) ไว้ให้
       นักพัฒนาเพียงทำหน้าที่เรียกใช้บริการเหล่านั้นผ่าน API/SDK โดยโมเดลแบบ BaaS ช่วยลดเวลาใน
       การพัฒนาโครงสร้างเซิร์ฟเวอร์ และลดค่าใช้จ่ายในการบำรุงรักษา

                2.2.2.3 แนวคิดแบบไร้เซิร์ฟเวอร์ (Serverless Architecture): เป็นแนวคิดที่นักพัฒนา
       ไม่ต้องบริหารจัดการระบบปฏิบัติการ (OS) หรือโครงสร้างพื้นฐานเซิร์ฟเวอร์ด้วยตนเอง การขยายตัว
       ของระบบ (Scaling) และการจัดสรรทรัพยากรการประมวลผลจะเป็นไปโดยอัตโนมัติตามปริมาณการ
       เรี ย กใช้ ง านจริ ง ซึ ่ ง เหมาะสมอย่ า งยิ ่ ง กั บ การสร้ า งระบบตรวจเช็ ค ที ่ ม ีป ริ ม าณการใช้ ง านแบบ
       เฉพาะเจาะจงในแต่ละช่วงวัน


       2.2.3 เทคโนโลยี Google Firebase
                Google Firebase เป็นแพลตฟอร์มการให้บริการหลังบ้านแบบ BaaS ที่ทำงานร่วมกันอย่าง
       เป็นระบบ โดยบริการหลักที่ประยุกต์ใช้ในโครงงานนี้ ได้แก่:

                         2.2.3.1 Firebase Authentication: เป็นระบบการยืนยันตัวตนและการจัดการ
                สิทธิ์ผู้ใช้ที่มีความปลอดภัยสูง ทำหน้าที่บริหารจัดการกระบวนการเข้าสู่ระบบ (Sign-in) ผ่าน
                ขั้นตอนการตรวจสอบความถูกต้องของอีเมลและรหัสผ่าน โดยระบบจะออกโทเค็นเพื่อความ
                ปลอดภัย (Secure Session Tokens) และจัดการสถานะผู้เข้าใช้งาน (Active Session
                State) บนเครื่องลูกข่ายโดยอัตโนมัติ เพื่อคัดกรองบุคคลที่ไม่มีสิทธิ์เข้าถึงระบบข้อมูลของ
                องค์กร
2.2.3.2 Cloud Firestore (NoSQL Document Database):

-     แนวคิดฐานข้อมูล NoSQL แบบ Document-Oriented: แตกต่างจากฐานข้อมูล
      เชิงสัมพันธ์ (Relational Database) ในอดีต โดย Cloud Firestore จะไม่เก็บ
      ข้ อ มู ล ในรู ป แบบตาราง (Tables) แต่ จ ะเก็ บ ข้ อ มู ล ในรู ป แบบของ "เอกสาร"
      (Documents) และ "กลุ่มเอกสาร" (Collections)

-     โครงสร้างข้อมูล: แต่ละ Document จะบรรจุข้อมูลในรูปแบบโครงสร้าง JSON-
      like (Key-Value Pairs) ซึ่งรองรับ ประเภทข้ อ มู ล ที่ห ลากหลาย เช่น String,
      Number, Boolean, Array, Map และ Geopoint โครงสร้างแบบนี้มีความยืดหยุ่น
      สู ง สามารถปรั บ ปรุ ง ฟิ ล ด์ ข ้ อ มู ล ได้ ต ามต้ อ งการโดยไม่ ส ่ ง ผลกระทบต่ อ สกี มา
      (Schema) ของตารางทั้งหมด

-     การสื่อสารข้อมูลแบบเรียลไทม์ (Real-time Synchronization): ทำงานบน
      โปรโตคอล WebSockets เพื่อสร้างการเชื่อมต่อแบบต่อเนื่องระหว่างแอปพลิเคชัน
      กับระบบฐานข้อมูลคลาวด์ เมื่อมีการเปลี่ยนแปลงข้อมูลใด ๆ ใน Firestore ระบบ
      จะส่งสัญญาณการเปลี่ยนแปลง (Update Event) ไปยังฝั่งผู้ใช้งานที่เปิดระบบอยู่
      ทันทีโดยอัตโนมัติ ทำให้หน้าจอรายงานสถานะอุปกรณ์แสดงผลแบบเรียลไทม์โดยไม่
      ต้องทำการรีเฟรชหน้าจอ

    2.2.3.3.1 Firebase Hosting:
            เป็นบริการโฮสต์สำหรับเว็บแอปพลิเคชันแบบสแตติก (Static Web Apps) ที่
    มีความมั่นคงปลอดภัยและให้ประสิทธิภาพในการโหลดหน้าเว็บสูง โดยระบบจะทำการ
    กระจายข้อมูล หน้า เว็บ ไปจัด เก็ บยัง เครือ ข่า ยส่ง มอบข้ อ มูล ระดับโลก (Content
    Delivery Network หรือ CDN) ที่อยู่ใกล้เคียงกับผู้ใช้งานมากที่สุด และใช้มาตรฐาน
    การสื ่ อ สารผ่ า นโปรโตคอล HTTPS (SSL/TLS) โดยเริ ่ม ต้น เพื่ อ รั บประกัน ความ
    ปลอดภัยของช่องทางรับส่งข้อมูล
       2.2.4 ทฤษฎีการจัดการสิทธิ์การเข้าใช้งานและความมั่นคงปลอดภัย (Access Control &
Security)

               2.2.4.1 การกำหนดสิทธิ์ตามบทบาทหน้าที่ (Role-Based Access Control หรือ
       RBAC): เป็นหลักการออกแบบระบบความปลอดภัยโดยกำหนดสิทธิ์การเข้าถึงข้อมูลและฟังก์ชันการ
       ทำงานตามบทบาท (Roles) ของผู้ใช้งานในระบบ เพื่อป้องกันการเข้าถึงข้อมูลที่อยู่นอกเหนือขอบเขต
       หน้าที่ความรับผิดชอบ โดยในระบบนี้จะจัดแบ่งผู้ใช้ออกเป็นสองบทบาทอย่างชัดเจน คือ บทบาท
       เจ้าหน้าที่ (Staff Role) และบทบาทผู้ดูแลระบบ (Admin Role)

               2.2.4.2 กฎความปลอดภัยคลาวด์ (Cloud Firestore Security Rules): เป็น
       สถาปัตยกรรมการตรวจยืนยันสิทธิ์ในฝั่งเซิร์ฟเวอร์คลาวด์ (Server-Side Validation) ของ Firebase
       โดยเมื่อฝั่ง Client มีการส่งคำสั่งอ่านหรือเขียนข้อมูล (Read/Write Requests) เข้ามา กฎความ
       ปลอดภัยจะทำหน้าที่ประเมินความถูกต้องของคำขอ โดยอิงกับสถานะล็อกอินของผู้ใช้และสิทธิ์การ
       ทำงานที่กำหนดไว้ เพื่อป้องกันการพยายามเจาะระบบหรือดึงข้อมูลผ่านทาง API จากภายนอกโดยมิ
       ชอบ
2.3 งานวิจัยที่เกี่ยวข้อง

พื้นฐานไอทีรายวันด้วยเทคโนโลยีคลาวด์ไฟร์เบส ผู้รายงานได้ศึกษา ค้นคว้า และทบทวนวรรณกรรมจาก
งานวิจัย โครงงาน และรายงานวิชาการที่เกี่ยวข้อง เพื่อใช้เป็นแนวทางและหลักการในการพัฒนาระบบ ดั งมี
รายละเอียดดังต่อไปนี้

        ตรวจสอบสถานะการทำงานของอุปกรณ์กระจายสัญญาณเครือข่ายไร้สาย" โดยพัฒนาแอปพลิเค
        ชันระบบสารสนเทศเพื่อตรวจสอบสถานะของอุปกรณ์ Access Point และ Switch ภายในพื้นที่
        มหาวิทยาลัย โดยระบบดังกล่าวถูกออกแบบให้อ่านสถานะของอุปกรณ์และส่งข้อมูลเชื่อมโยงเข้าสู่
        ฐานข้อมูลคลาวด์ Firebase ร่วมกับการแสดงผลฝั่ง Client-side ผ่านเว็บแอปพลิเคชัน เพื่อช่วยให้
        เจ้าหน้าที่ฝ่ายไอทีได้รับแจ้งข้อมูลความผิดปกติได้อย่างรวดเร็วและแม่นยำ

                            - ความเชื่อมโยงและประโยชน์ต่อโครงงาน: งานวิจัยนี้แสดงให้เห็นความสำคัญของ
                 การติดตามสถานะโครงสร้างพื้นฐานเครือข่ายคอมพิวเตอร์ ซึ่งสอดคล้องกับโครงงานของ
                 ผู้รายงานในการจัดทำโมดูลตรวจสอบอุปกรณ์ Server, Network และ CCTV นอกจากนี้ยัง
                 เป็นการยืนยันความเหมาะสมในการเลือกใช้ฐานข้อมูลคลาวด์ในการรวบรวมสถานะอุปกรณ์
                 จากระยะไกล
